ZEN AI极简款

这款无屏智能戒指的核心目标是：**用最低的硬件复杂度，实现与 Claude Desktop 的稳定连接、实时状态感知和可靠的权限审批交互**。

下面是为你整理的详细设计方案，从硬件选型到软件开发都包含在内。

### 📋 极简款硬件规格清单

| 模块 | 选型/规格 | 备注 |
| - | - | - |
| **主控芯片 (SoC)** | **nRF54L15** (Nordic) | 首选。Cortex-M33 @ 128MHz，1.5MB NVM + 256KB RAM，超低功耗，完美支持BLE NUS协议。 |
|  | 或 **nRF52840** | 备选。性能稍弱但生态更成熟，可直接参考现成开源项目。 |
| **无线连接** | 集成于主控，支持 **BLE 5.0+** | 必须实现 **Nordic UART Service (NUS)**，用于收发JSON指令。 |
| **姿态传感器 (IMU)** | **BMI270** (Bosch) 或 **ICM-42670-P** (TDK) | 6轴（陀螺仪+加速度计）。用于手势识别（如双击、旋转）来触发功能。 |
| **触觉反馈** | **微型线性马达** + **AW86235CSR** 驱动芯片 | 通过不同震感区分“请求”、“成功”、“错误”等状态。 |
| **状态指示灯** | **WS2812B-2020** (或同系列) | 极简信息反馈。可用颜色/闪烁代表：待机（绿）、请求（黄色闪）、报警（红色），成功（绿闪）等。 |
| **电池** | **19-21mAh** 弧形锂聚合物电池 | 需定制尺寸以适配戒圈内壁弧度。 |
| **电源管理** | **AW32012CSR** (充电管理) + **AW37030D110DNR** (LDO) | 支持NFC无线充电或磁吸触点充电。 |
| **充电方案** | **NFC 无线充电** (推荐) | 采用ROHM等提供的2.5mm级微型NFC充电芯片，效率约45%，实现全封闭防水结构。 |
| **结构件** | **柔性电路板 (FPC)** + **钛合金/陶瓷外壳** | FPC是必须项，用于在狭窄空间内连接所有元件。 |
| **防水等级** | 目标 **IP68 / 5ATM** | 需全封闭式设计，无物理按键开口。 |
| **尺寸与重量** | 重量 \< **6g**，宽度约 **8-10mm** | 参考追觅Glow (3.8g) 和 VisRing (6.6g) 的轻量化设计。 |


### ⚙️ 核心功能与软件逻辑

**1. BLE 通信与 Claude Desktop 协议对接**

- 固件需实现标准的 **NUS (Nordic UART Service)** 服务。

- 收发 **JSON 格式** 数据包，核心字段示例：

\{  
"type": "permission\_request",  
"id": "req\_123",  
"text": "Claude wants to read file X. Allow?"  
\}

```
    
- 回复批准/拒绝指令：    
    
- \\\`\\\`\\\`    
\\\\\\\{"type": "permission\\\\\\\_response", "id": "req\\\\\\\_123", "allow": true\\\\\\\}
```

**2. 手势交互定义**

- **双击**：批准当前请求 (Allow)。

- **长按 1秒**：拒绝当前请求 (Deny)。

- **旋转手腕/翻转**：可预留为“忽略”或“静音”功能。

- 手势识别可借助 **ESP-DL** 或 **TensorFlow Lite Micro** 在本地运行轻量模型，或使用简单的阈值算法（节省资源）。

**3. 状态反馈映射**

- **LED 颜色**：

  - 待机/连接成功：**慢闪绿色** (每3秒一次)

  - 收到权限请求：**快速闪烁红色** (2Hz)

  - 请求已批准：**绿色长亮1秒**

  - 请求已拒绝：**红色长亮1秒**

  - 低电量：**橙色闪烁**

- **震动模式**：

  - 权限请求：短-短-长震动

  - 批准成功：短震一下

  - 拒绝成功：两下短震

**4. 低功耗策略**

- **广播与连接间隔**：设置合适的连接参数，如连接间隔 30ms-50ms，从机延迟启用。

- **深度睡眠模式**：无连接时进入睡眠（电流 \<5µA），通过 RTC 定时唤醒广播，或由 IMU 中断唤醒。

- **IMU 间歇采样**：手势检测采用低频采样（如 25Hz），仅在检测到可能的手势事件时才提高采样率。

### 🚀 开发路径建议

1. **第一阶段：协议验证**

   - 使用现成的 **M5StickC Plus** 或 **nRF52840-DK** 开发板，烧录 Claude Desktop Buddy 官方固件，确保能成功连接并收发 JSON 数据。

   - 在此基础上修改代码，加入 LED 和震动反馈逻辑，模拟极简款的行为。

2. **第二阶段：原型机制作**

   - 设计第一版 **FPC 软板**，集成 nRF54L15、IMU、LED、马达驱动和电源管理。

   - 采用 **3D 打印** 外壳进行功能验证和尺寸适配。

3. **第三阶段：固件开发**

   - 移植或重写 BLE NUS 服务。

   - 实现手势识别算法（初期可用阈值判定，后期可升级为轻量 AI 模型）。

   - 完善电源管理代码。

4. **第四阶段：结构优化与量产准备**

   - 开模制作钛合金/陶瓷外壳。

   - 通过 FCC/CE 认证，确保 BLE 合规性。

   - 解决小尺寸天线设计及信号衰减问题。

### ⚠️ 潜在挑战提醒

- **天线设计**：金属外壳会严重屏蔽信号，需要在戒圈外侧或特定位置设计天线窗口（如陶瓷材质区域）。

- **发热问题**：无线充电和密集运算时可能会有温升，需通过低功耗设计和散热结构优化。

- **手势误触**：极简交互需反复调优算法，避免日常动作被误判为“批准”指令。

### 💎 总结

极简款的核心在于 **“做减法”**：去掉屏幕、去掉实体按键，用最少的元件实现可靠连接和明确反馈。nRF54L15 芯片提供的强大算力与超低功耗，足以承载手势识别等进阶功能，为未来迭代留出空间。
