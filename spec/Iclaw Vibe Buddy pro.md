这款OLED旗舰款的目标是在此基础上进一步“丰富感知”，成为功能全面的信息中枢。下面是整合后的详细硬件方案。

### 📋 OLED旗舰款硬件规格清单

| 模块 | 选型/规格 | 备注 |
| - | - | - |
| **主控芯片 (SoC)** | **nRF54L15** (Nordic) | 首选。128MHz Cortex-M33 + RISC-V协处理器，1.5MB NVM + 256KB RAM，超低功耗，处理能力较上代提升一倍。 |
|  | 或 **Apollo330B Plus** (Ambiq) | 备选。250MHz，2MB SRAM + 2MB Flash，BLE 5.4，专为边缘AI设计，功耗低至6µA/MHz。 |
| **芯片模组** | **BCL603S2H** (勇芯科技) | 推荐。5×5mm Chiplet封装，集成了nRF54L15 + PMIC + LDO，可直接采购加速开发。 |
| **显示方案** | **柔性OLED屏幕** | 首选：**160x32**像素，4-bit灰度，270°~360°环绕包裹。备选：0.7英寸全彩OLED (320x240像素)。 |
| **触摸与手势** | **电容式触摸传感器** | 覆盖屏幕表面，支持轻触、滑动导航。也可配合IMU实现手势识别，用于拒绝、忽略、唤醒等操作。 |
| **传感器 (IMU)** | **BMI270** (Bosch) 或 **ICM-42670-P** (TDK) | 6轴（陀螺仪+加速度计）。与极简款相同。 |
| **触觉反馈** | **微型线性马达** + **AW86235CSR** 驱动芯片 | 与极简款相同。 |
| **状态指示灯** | **WS2812B-2020** (或同系列) | 可选。当屏幕休眠时作为低功耗替代，或与屏幕配合使用。 |
| **电池** | **24-25mAh** 弧形锂聚合物电池 | 因屏幕功耗更高，容量需比极简款增加约20%。 |
| **电源管理** | **AW32012CSR** (充电管理) + **AW37030D110DNR** (LDO) | 与极简款相同，也可采用BCL603S2H模组内置的PMIC+LDO。 |
| **充电方案** | **NFC无线充电** (推荐) | 采用ROHM等提供的微型NFC充电芯片，实现全封闭防水结构。 |
| **结构件** | **柔性电路板 (FPC)** + **钛合金/陶瓷外壳** | FPC是必须项，用于在狭窄空间内连接所有元件。屏幕需沿指环弧度包裹。 |
| **防水等级** | 目标 **IP68 / 5ATM** | 需全封闭式设计，屏幕与外壳的结合处须特殊防水处理。 |
| **尺寸与重量** | 重量约 **6.6g**，宽度约 **8-10mm** | 参考VisRing (6.6g)，在同级带屏戒指中属于轻量级。 |


### ⚙️ 核心功能与软件逻辑

OLED旗舰款的核心交互将从“被动响应”升级为“主动感知”：

**1. 全功能BLE通信与协议对接** 与极简款相同，但新增对自定义GIF角色的完整支持。固件需接收并渲染来自Claude Desktop的GIF动画包（manifest.json + 96像素宽的GIF文件）。

**2. 状态反馈映射（屏幕版）** 利用屏幕能力实现更丰富、直观的状态反馈，如所描述的7种核心状态：

| Claude状态 | 屏幕显示 | 震动模式 | LED（可选） |
| - | - | - | - |
| **睡眠 (Sleep)** | 宠物闭眼睡觉动画 | 无 | 无 |
| **待机 (Idle)** | 宠物轻轻眨眼 | 无 | 慢闪绿色 |
| **忙碌 (Busy)** | 忙碌或流汗动画 | 无 | 绿色呼吸 |
| **等待审批 (Attention)** | **黄色背景 + 请求内容文字 + “A批准 B拒绝”** | 短-短-长震动 | 黄色2Hz闪烁 |
| 警告（Warning) | 红色 | 短-短-长震动 | 红色急速闪烁 |
| **庆祝 (Celebrate)** | 庆祝动画 + “累计消耗xx tokens” | 长震一下 | 绿色闪烁 |
| **眩晕 (Dizzy)** | 眩晕动画（快速摇晃触发） | 无 | 无 |
| **快速审批 (Heart)** | 爱心飘出动画 | 短震一下 | 无 |


**3. 触摸+手势双重交互**

- **屏幕触摸**：轻触→唤醒屏幕，滑动→浏览消息，点击→批准（A键模拟）/ 拒绝（B键模拟）

- **IMU手势**：双击→批准请求，长按1秒→拒绝请求，旋转手腕→忽略或静音。触摸与手势可互为备份，提升可靠性

**4. 自定义角色包（旗舰专属功能）**

- 用户可将角色包文件夹拖拽到Claude Desktop界面，客户端通过BLE将GIF资源流式传输到戒指。

- 角色包结构：`manifest.json`（定义颜色方案与状态映射） + 一组96像素宽的GIF文件，总大小不超过**1.8MB**。

**5. 低功耗优化策略**

- **屏幕休眠**：无操作后**30秒**自动熄屏，有审批请求时强制常亮

- **连接间隔优化**：BLE连接间隔设置为30-50ms，启用从机延迟

- **深度睡眠**：无连接时进入睡眠（电流\<5µA），RTC定时唤醒或IMU中断唤醒

- **IMU间歇采样**：低频采样（25Hz），仅在手势事件触发时提高采样率

### 🏆 与极简款的核心差异

| 对比维度 | 极简款 | OLED旗舰款 |
| - | - | - |
| **主控方案** | nRF54L15或nRF52840 | nRF54L15 (首选) 或 Apollo330B Plus (备选) |
| **信息反馈** | LED单色/闪烁 | **柔性OLED，可显示文字、动画、GIF** |
| **交互方式** | 纯手势（双击/长按） | **手势 + 触摸屏双重交互** |
| **角色自定义** | 不支持 | **支持上传自定义GIF角色包** |
| **电池容量** | 19-21mAh | 24-25mAh |
| **目标续航** | 7-10天 | 5-7天（屏幕开启会显著缩短续航） |
| **BOM成本** | 较低 | 较高，主要增量来自OLED屏幕和触摸传感器 |
| **开发复杂度** | 低 | 高，需要处理显示驱动、UI框架和功耗优化 |


### ⚠️ 技术挑战与应对方案

- **屏幕功耗**：OLED显示是耗电大户。需实现智能熄屏策略（无操作30秒熄屏），仅在必要时唤醒。

- **曲面触摸精度**：指环表面积极小，触摸定位困难。初期可放弃精确定位，仅支持“轻触”和“滑动”两种粗粒度手势。

- **天线信号屏蔽**：金属外壳会严重衰减BLE信号。需在戒圈外侧设计天线窗口（如陶瓷材质区域），或采用LDS激光直接成型天线。

- **屏幕耐用性**：柔性OLED相对脆弱，需通过结构设计保护，防止日常佩戴中的刮擦、水渍和冲击。

- **发热问题**：无线充电和密集运算时可能温升，需优化充电策略和散热结构。

### 🚀 开发路径建议

1. **阶段一：显示验证**

   - 使用现成的OLED开发板（如M5StickC Plus）测试160x32柔性屏的驱动与基础UI渲染。

   - 验证Claude Desktop Buddy的GIF角色包传输与显示能力。

2. **阶段二：原型机制作**

   - 设计第一版FPC软板，集成nRF54L15模组、柔性OLED、触摸传感器、IMU、马达驱动和电源管理。

   - 采用3D打印外壳进行功能验证和尺寸适配。

3. **阶段三：固件开发**

   - 移植BLE NUS服务与JSON协议。

   - 实现触摸+手势识别算法，建立状态机管理7种Claude状态。

   - 完善电源管理代码，重点优化屏幕休眠策略。

4. **阶段四：结构优化与量产准备**

   - 开模制作钛合金/陶瓷外壳，解决屏幕防水与天线信号问题。

   - 通过FCC/CE等认证，确保BLE合规性。

这样规划之后，两款戒指的定位就非常清晰了：极简版追求**稳定连接、极低成本、超长续航**，OLED旗舰版则追求**信息可视、交互丰富、功能全面**。两者共享同一套BLE协议和核心固件框架，可以并行开发，先在极简版上验证连通性，再在旗舰版上叠加显示和触摸功能。
